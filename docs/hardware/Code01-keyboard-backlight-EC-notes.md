# Code01 / PF5NU1G 键盘背光 EC 协议观测记录

> 机型：MECHREVO Code01（PF5NU1G）· EC 访问：`\\.\ACPIDriver` 窗口通道 0x700-0x7FF
> 目的：把这台机器白色键盘背光的全部实测数据摊开，请熟悉 EC/ACPI 的同学帮忙判断剩下的那个问题。
> 结论先放这里：**按键（固件）改 `0x78C` 灯会变；软件通过 ACPI 窗口改同一个字节，回读一致但灯不变。**

## 1. 现象与核心疑问

| 谁写 `0x78C` | 回读 | 灯 |
|---|---|---|
| 机身上的亮度快捷键（EC 固件自己） | 值变化 | **跟着变** |
| 软件经 ACPI 窗口写（`\\.\ACPIDriver` + IOCTL） | **写什么读到什么** | **不变** |

同一个地址、同一个值、同样的低位保留策略，结果不同。想请教：

1. 这种"回读一致但硬件无响应"最常见的成因是什么？（EC 影子 RAM / bank 切换 / 该页只读回显 / 需要命令口提交）
2. EC 侧是否存在"命令字节 + 参数"的间接通道？我们从窗口只看到数据区，没找到命令对。
3. `0x70F` 每次按键 +1，它是不是某种"事件/请求计数"，能否被软件用作触发？

## 2. 寄存器地图（均为 0x700-0x7FF 窗口内实测）

### 2.1 `0x78C` —— 键盘背光状态/档位

| 位 | 含义 | 依据 |
|---|---|---|
| bit0 | 恒为 1，用途未知，任何写入都保留原值 | 全部抓包中始终为 1 |
| bit1 | 关灯位（1 = 关） | 同厂控制台开关实现：开 → `b &= 0xFD`，关 → `b |= 0x02` |
| bit4 | 提交位（写完档位必须置 1，随后被固件自清） | 同厂控制台单色键盘实现 |
| bit5 | 档位第 0 位（1 → 档 1，暗） | `level = b >> 5`，实测 `0x21` |
| bit6 | 档位第 1 位（1 → 档 2，亮） | 实测 `0x41`；bit5+bit6 = 档 3 |
| bit7 | 档位第 2 位（档 4，控制台档位上限 4） | `level << 5` 公式 |

本机只有 2 档，实际出现过的值：`0x01`（关）、`0x21`（暗）、`0x41`（亮）、`0x03`/`0x23`（关，带关灯位/带记忆档）。

### 2.2 同厂控制台程序里单色键盘的位运算

```csharp
// 读档位
Read(0x78C, ref b);  level = b >> 5;

// 写档位
Read(0x78C, ref b);
b |= 16;                    // 0x10 提交位
b &= 31;                    // 0x1F 保留 bit0~bit4（含关灯位 bit1），清档位位
b |= (byte)(level << 5);
Write(0x78C, b);

// 电源
Read(0x78C, ref b);
if (on) b &= 253; else b |= 2;   // 0xFD / 0x02
Write(0x78C, b);
```

档位常量：最小 0、最大 4、交流默认 2、电池默认 0。

### 2.3 其它相关地址

| 地址 | 行为 | 判断 |
|---|---|---|
| `0x767` | bit5 脉冲 `0x10 → 0x30 → 0x10`；bit4 常态为 1（关机 USB 给电）；bit0 快捷开关翻转 | 多通道共享命令字节。**按键调亮度时它不动**，软件以前会误发脉冲 |
| `0x70F` | 每次按亮度键 +1（`00→01→02…08`），约在 `0x78C` 变化后 215 ms | 按键事件计数 |
| `0x70A` | 无人操作也单调递增（`0x14→0x38`） | EC 内部计数/时间基准 |
| `0x766` = `0xD0`、`0x78E` = `0x08`、`0x740` = `0x09` | 静态 | 机型/项目相关常量 |

## 4. 已尝试并排除的假设

| 假设 | 实验 | 结果 |
|---|---|---|
| 需要 `0x767` bit5 脉冲提交 | 写完 `0x78C` 后把 `0x767` 或上 0x20 发脉冲 | 按键路径根本不发脉冲；发与不发灯都不变 ⇒ 脉冲无关，已移除 |
| 关灯必须写 `0x03`（带 bit1） | 对照固件的 `0x01` | 固件只清档位位；两种写法都不点灯 ⇒ 不是关灯值问题 |
| 需要 bit4 提交位 | 按同厂公式写 `0x31/0x51/0x11` | 全窗口扫描显示固件按键时不写 bit4 ⇒ 本机不需要；软件补上也无害（回读后自清） |
| OSD/档位换算错 | 按 `bit5=档1、bit6=档2` 重算 | 已修正，显示与 EC 实际一致 |
| 读旧值导致跳档 | 改为"只读不写"，按键完全交固件 | 跳档消失 ⇒ 之前的"闪一下 2"是软件按旧读数回写造成的 |

## 5. 当前实现（LM / L-Mechrevo）

- 亮度键：声明 `hotkey=0` ⇒ **软件不回写**，按键后 120 ms 读 `0x78C` 出 OSD
- 面板滑块：保留（按机主要求），走"读-改-写 `0x78C`"，观测到**灯无反应**
- 亮灭判定：电源位 bit1 与档位位分开判（关灯时固件会保留档位位做记忆，如 `0x23`）

## 6. 复现工具

两个只读/可控写入的脚本（管理员运行，仅 0x700-0x7FF 窗口通道，不做 EC 端口 I/O）：

```
kbd-ec-capture.ps1  -Seconds 0 -IntervalMs 150 -Regs 0x78C,0x767,0x70F,0x70A
kbd-ec-probe.ps1    -Mode window -Seconds 60           # 全窗口 diff
kbd-ec-probe.ps1    -Mode write  -Addr 0x78C -Value 0x41 -IUnderstandWrite
```
